1. Introduction

This is a simple specification aimed at assisting developers building algorithmic-based MCP / CLI agentic tooling which have high Developer and Agent Experience (DX/AX). The majority of MCPs and CLIs relate to accessing data, however there is a growing demand for agentic tooling which surface algorithms such as predictive model inference, business logic and optimisation. The vast design and execution space for these tools, caused by their flexible nature, often results in poor AX and inconsistent implementation / documentation. Much of this information ends up buried in tool descriptions as free text — algoto provides a structured, machine-readable format for it instead.

This spec attempts to close this gap, covering foundational elements of the design space for algorithms. A development team which builds many sets of agentic tools, surfacing a wide range of algorithms, will benefit from having a common specification for their tools to adhere to. This specification extends and builds on top of MCPs annotations (agent hints), setting out guidelines specific for this class of tooling.

1.1 Complementarity

An algoto document only carries information your tool's source code and annotations cannot already express. Function signatures, type hints, default values, docstrings and validation rules all belong in your code. algoto adds the things code can't say: what class of algorithm is running, whether it's deterministic, how each input shifts the output, what the numbers in the response actually mean, and what to do when something fails.

Your source code already definesalgoto adds
Function name, docstring, parameter namesAlgorithm family (prediction, simulation, etc.), method summary, internal steps
Type hints, defaults, validation boundsWhether the algorithm is deterministic, approximate, or seeded
Input parameter types and validationEach input's role (data vs tuning parameter), its effect on the output, and its units
Return type and response shapeWhat each output field means, its units, and how uncertainty is expressed
Async/await, job queue mechanicsExpected latency class, companion polling tool and interval
Exception types and error responsesWhen each error fires and what the caller should try next

2. Example

A forecasting tool written the usual way:

@mcp.tool()
def forecast_demand(
    history: list[Observation],
    horizon_days: int = 14,
    interval_level: float = 0.9,
) -> Forecast: ...

The algoto document beside it:

{
  "algoto": "1.0",
  "name": "forecast_demand",
  "algorithm": {
    "type": "prediction",
    "description": "Seasonal exponential smoothing with a weekly cycle, fit per call on the supplied history.",
    "steps": [
      "Validate and gap-fill the sales history",
      "Fit trend and weekly seasonality components",
      "Project forward over the requested horizon",
      "Derive prediction intervals from in-sample residuals"
    ],
    "deterministic": true,
    "version": "2.1.0"
  },
  "inputs": {
    "history": { "role": "data", "units": "units/day" },
    "horizon_days": {
      "role": "parameter",
      "units": "days",
      "effect": "Longer horizons widen the prediction intervals."
    },
    "interval_level": {
      "role": "parameter",
      "units": "probability 0–1",
      "effect": "Higher coverage widens the bounds; the point estimate is unaffected."
    }
  },
  "outputs": {
    "forecast": {
      "units": "units/day",
      "uncertainty": "lower/upper bounds at the requested interval_level accompany each point estimate",
      "interpretation": "The point estimate is the median outcome; plan capacity against the upper bound."
    }
  },
  "guardrails": {
    "constraints": [
      {
        "rule": "horizon_days <= length(history) / 2",
        "on_violation": "reject",
        "description": "Supply more history or shorten the horizon."
      }
    ]
  },
  "execution": { "mode": "sync", "latency": "instant" },
  "errors": [
    {
      "when": "history contains fewer than 28 days after gap-filling",
      "hint": "Fetch a longer sales history and retry."
    }
  ]
}

You could put all of this in a tool's description string, but algoto gives a formalised, machine-readable structure for expressing it — consistent across tools and teams.

3. Attachment to Agent

The document shape is the same everywhere. Only delivery differs.

3.1 Join key

name must exactly match the tool it annotates — the MCP tool name or CLI subcommand.

3.2 MCP servers

Use the MCP protocol's meta field on the tool definition to attach the document. This keeps the annotation structured and separate from the tool's description.

import json
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("forecasting")

ALGOTO_DOC = {
    "algoto": "1.0",
    "name": "forecast_demand",
    "algorithm": {
        "type": "prediction",
        "description": "Seasonal exponential smoothing with a weekly cycle.",
        "deterministic": True,
        "version": "2.1.0",
    },
    "inputs": {
        "horizon_days": {
            "effect": "Longer horizons widen the prediction intervals."
        }
    },
    "outputs": {
        "forecast": {
            "units": "units/day",
            "interpretation": "The point estimate is the median outcome."
        }
    },
}

@mcp.tool(meta={"algoto": ALGOTO_DOC})
def forecast_demand(
    history: list[dict],
    horizon_days: int = 14,
    interval_level: float = 0.9,
) -> dict:
    """Forecast demand from historical observations."""
    ...

3.3 CLI

Ship a sidecar <tool_name>.algoto.json and support --algoto on each subcommand to print it.

3.4 Validation

Any JSON Schema 2020-12 validator can check a document:

check-jsonschema --schemafile algoto-1.0.schema.json forecast_demand.algoto.json

Every key in inputs and outputs, and any seed_input, must name a real parameter or field of the tool. This is not enforced by the schema validator.

5. Algorithm

Describes what the tool does under the hood.

PropertyTypeDescription
typeenumprediction, classification, optimisation, simulation, estimation, transformation, other.
descriptionstringOne plain-language line describing the method.
stepsarray of stringShort list of internal steps, in order.
deterministicbooleanTrue when identical inputs always produce identical outputs. Agents can use this to cache results for repeated calls.
parallelisablebooleanTrue if multiple calls can safely run concurrently with no shared state or ordering dependency.
seed_inputstringName of the parameter that pins randomness.
approximatebooleanTrue if the output is an approximation (heuristic, time-bounded, sampling-based).
versionstringAlgorithm version. Bump when outputs change for identical inputs.
"algorithm": {
  "type": "prediction",
  "description": "Seasonal exponential smoothing with a weekly cycle, fit per call on the supplied history.",
  "steps": [
    "Validate and gap-fill the sales history",
    "Fit trend and weekly seasonality components",
    "Project forward over the requested horizon",
    "Derive prediction intervals from in-sample residuals"
  ],
  "deterministic": true,
  "version": "2.1.0"
}

6. Inputs

Per-parameter annotations, keyed by the exact parameter name. Each annotation must contain at least one property.

PropertyTypeDefaultDescription
roleenumparameterdata is what the tool runs on, parameter tunes it, seed pins randomness.
effectstringHow changing this input moves the output.
unitsstringUnits or scale.
"inputs": {
  "history": { "role": "data", "units": "units/day" },
  "horizon_days": {
    "role": "parameter",
    "units": "days",
    "effect": "Longer horizons widen the prediction intervals."
  }
}

Types, defaults, descriptions, required flags and enum values belong in the tool's input schema, not here.

7. Outputs

Per-field annotations, keyed by field name. Each annotation must contain at least one property.

PropertyTypeDescription
unitsstringUnits or scale of the field.
uncertaintystringHow uncertainty is expressed for this field.
interpretationstringHow to read the value.
"outputs": {
  "forecast": {
    "units": "units/day",
    "uncertainty": "lower/upper bounds at the requested interval_level accompany each point estimate",
    "interpretation": "The point estimate is the median outcome; plan capacity against the upper bound."
  }
}

8. Guardrails

Cross-input constraints and rate limits, stated so agents do not discover them by trial and error.

PropertyTypeDescription
constraintsarrayRules across parameters. Each has a rule, optional on_violation, and optional description.
rate_limitstringCall budget in plain words.

8.1 Constraint fields

PropertyTypeDefaultDescription
rulestringReadable constraint over parameter names. Not machine-evaluated.
on_violationenumrejectreject or warn.
descriptionstringWhat the agent should do instead.
"guardrails": {
  "constraints": [
    {
      "rule": "horizon_days <= length(history) / 2",
      "on_violation": "reject",
      "description": "Supply more history or shorten the horizon."
    }
  ]
}

9. Execution

PropertyTypeDefaultDescription
modeenumsyncsync or async.
latencyenumundeclaredinstant (<1s), seconds (<30s), minutes (<10min), long.
asyncobjectPolling hints when using a paired-tool async pattern.

9.1 Async

When the stack provides protocol-level async (e.g. MCP Tasks), it owns the polling mechanism and no async block is needed. Declare poll_tool only when the server uses a paired-tool pattern — a start tool plus a separate result-retrieval tool.

PropertyTypeDescription
poll_toolstringCompanion tool to poll for results.
poll_intervalnumberPolling interval in seconds.
"execution": {
  "mode": "async",
  "latency": "minutes",
  "async": {
    "poll_tool": "get_schedule_result",
    "poll_interval": 10
  }
}

10. Errors

Known failure modes with recovery hints. Error codes and response shapes stay in the tool definition.

PropertyTypeRequiredDescription
whenstringyesCondition that triggers the error.
hintstringnoWhat the agent should do next.
"errors": [
  {
    "when": "history contains fewer than 28 days after gap-filling",
    "hint": "Fetch a longer sales history and retry."
  }
]

11. Trust

An algoto document is metadata. Trust it exactly as much as you trust the tool's author.
